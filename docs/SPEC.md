Conventions. "Brain time" means simulated time; "wall time" means real time on Rolf's MacBook (Apple M5 Pro, 18 cores, 24 GB, macOS 26). "Root ID" means a FlyWire root ID, a 64-bit integer. "Index" means a neuron's row position in the engine's arrays, fixed per connectome version and stored with every run. "Population" means a named set of root IDs from the registry. "Compartment" means a named neuropil volume holding one dopamine concentration. "Engine tick" means an integer count of 0.1 ms steps since the engine's last build or restore; "recording tick" means engine tick minus the probe's recording start tick. Model constants live in section 5 and `data/params-v0.1.yaml`; calibrated and development values live in their named data files. `lif.g_inh` has bare default 1 and is pinned with a background drive table only when that layer is on. (item 44)

Four words are used with fixed meanings in section 7 and in every manifest. "Verification" means a check that the code computes what the equations say. "Consistency" means a check that the model behaves the way its own assumptions imply. "Calibration" means a bounded procedure that sets parameters against a reference and then freezes them. "Empirical validation" means a comparison against measured fly data that the parameters were not tuned on. "Prediction" means a recorded model outcome with no matching empirical reference. A test's category is part of its identifier.

## 1. Scope

### 1.1 What Phase 1 delivers

One honest end-to-end experiment on the whole-brain model, driven through a typed experiment file and a local tool server, with results stored with full provenance and shown on a minimal dashboard. Concretely:

- The Shiu 2024 leaky integrate-and-fire model rebuilt on FlyWire v783 inside a wrapper that gives every neuron its own threshold and gain, silences by threshold, drives neurons by Poisson input in two modes (the upstream's exact mode for reproduction and an extended mode for assays), and steps the network in 10 ms chunks so other components can act between chunks. The v630 build stays available so the published result can be reproduced exactly.
- A population registry built from the pinned and verified flywire_annotations v2.1.0 release, with weighted neuron-to-compartment and DAN-to-compartment maps for the mushroom body and central complex.
- The bare Shiu substrate, with `lif.g_inh` 1 and `background: false`, is the canonical model for reproduction, experiments, and pharmacology. The ratio-4 background drive and its spontaneous-rate targets are a development track, not a qualified Phase 1 layer. (item 47)
- Neuromodulation layer A (dopamine pools per compartment, receptor-typed gain and threshold changes) and layer C (transporter reuptake plus a non-transporter clearance, methylphenidate as a competitive blocker, 3-iodotyrosine as a release reducer, a vehicle no-op, oral pharmacokinetics). Layer B (receptor kinetics) and layer D (learning) are not built; their flags exist in the schema and are reported as absent.
- A closed loop from steering descending neurons to a virtual Buridan arena and back through a visual encoder into the anterior visual pathway, with a flashing distractor option, and metrics computed by one function for model and real trajectories, verified against the reference dataset's own published metric values.
- The experiment schema with paired arms, an orchestrator with a documented slow-state approximation between probes, a results store with a live stream, an MCP tool server, and a dashboard.
- Validation levels 0 to 4 as automated tests with categories, five artefact detectors, and a first experiment set: wild type, fumin, Dop1R1 null, and a dopamine-depleted state, each with vehicle and methylphenidate arms, ten seeds each, compared with the Colomb and Brembs 2014 Buridan trajectories where the data allow.

The bare substrate has no spontaneous DAN firing; Phase 1 uses the provisional tonic source in section 3.4. Its background-rate and resting-state claims remain development findings, and the section 3.5 behaviour gates require a matching bare-substrate calibration. (item 47) (item 51)

### 1.2 What Phase 1 does not deliver

No receptor kinetics or chronic adaptation (layer B), no learning (layer D), no atlas-derived receptor map (hand-curated only), no field-potential proxy or competing-flicker assay, no body, nerve cord, or optic-lobe image input, no octopamine, serotonin, glia, or gap junctions, no custom engine, no chat product (Claude Code or any MCP client is the plain-language layer), no physical arena, no neural memory across protocol phases (section 3.4). Amphetamine, atomoxetine, caffeine, and cocaine are schema-valid drug names that validation rejects with an explanatory error. Cirl is not represented; nothing in this spec is claimed equivalent to it.

### 1.3 Acceptance test

Input. Rolf, in Claude Code with the tool server attached, types: "give the wild-type fly 0.5 mM methylphenidate, wait two hours, then test Buridan fixation with a flashing distractor on the side". Claude Code translates that into the experiment file in section 6.3 (or an equivalent that validates against the schema): a paired design with a drug arm and a vehicle arm, both `wild_type`, identical in every resolved field except the drug name, ten seeds each. It calls `run_experiment`.

Outputs. A run directory under `runs/` containing, for every arm and seed, the spike table of every recorded population during every probe, population rates, the all-neuron 1 ms population count, the dopamine trace of every compartment, transporter and drug traces, the arena trajectory, and a metrics file with the fixation index, stripe deviation, walk count, and distractor switch rate per seed with mean, standard deviation, and a paired drug-minus-vehicle difference with a bootstrap 95 percent interval. A manifest that names the connectome version, annotation version, receptor map version, parameter, dopamine, and behaviour file versions, and the drive version only when background is on, code commit, `uv.lock` hash, every data file's checksum, the slow-state approximation, the layer flags, the protocol hash, every free parameter in force, and for every component its validation entries with the test identifiers and their binding. The dashboard shows the run. The bare run records `lif.g_inh: 1` and no drive hash. (item 44) (item 47)

Main acceptance predicate, every clause required:

1. The run completes without operator intervention within the wall budget of section 3.10, computed from the measured end-to-end throughput of benchmark B2.
2. Every output listed above exists, and `validate_run` (section 3.8) reports no missing field. Tables for populations that produced no spikes are valid empty tables with the right schema.
3. The manifest's validation entries match `validation/status.json`, every entry is valid for this run under the compatibility rule of section 7 (canonical-fixture tests match on code, environment, and data; matching-layers tests also match on layer flags; run-bound tests match on this experiment's protocol hash), none is stale, and every layer that is on is qualified under the component map in section 7.1: engine, registry, and neuromodulation meet their component requirements, and behaviour is at "level 4 closed-loop passed". With `background: false`, no drive record or background qualification is required. (item 47) (item 48)
4. The two-hour wait advances the pharmacokinetic state analytically in under one second of wall time, and the manifest records the slow-state approximation.
5. The transporter layer behaves as its own equations imply in the wild-type arms: the paired drug-minus-vehicle difference in mean compartment dopamine over the test probe, averaged over innervated compartments, has a bootstrap 95 percent interval lying entirely above zero, and the drug arm's methylphenidate brain concentration at the start of the test probe is positive and recorded. This is the wild-type counterpart of the fumin null clause of the signed-off draft, which is now test 3.4 only (resolution 8, section 10): it checks that the dose reached the model and acted through the transporter, the 0.5 mM point of the dose series of test 3.3. It makes no claim about behaviour. The paired fixation difference is reported as a prediction (test 4.7, wild-type entry) with no empirical reference (section 10, item 13).
6. A second, separate execution of the same file with the same seeds in the pinned environment reproduces every recording tick and every metric bit for bit. This execution is part of the acceptance validation and is budgeted in section 3.10.

Partial-delivery predicate. If test 4.1 finds the steering curve flat (section 7) and the fallback of section 9.1 is taken, Phase 1 may be delivered as "closed-loop not achieved": clauses 1, 2, 4, 5, and 6 hold for the open-loop version of the acceptance file, clause 3 holds with the behaviour component at "level 4 open-loop only", and the summary, the dashboard, and `docs/phase1-results.md` all carry that status on their first line. Partial delivery never satisfies the main predicate.

## 2. Repository layout and runtime

### 2.1 Runtime

Python 3.12 managed by uv, in the existing `.venv` at the repository root. Brian2 2.10.1 with the Cython runtime backend, which the proof run verified on this machine with Apple clang; the Cython cache goes under `.cache/brian2`. C++ standalone mode is not used because it cannot stop every 10 ms to let the arena and pools act. Runtime dependencies: NumPy 2.x, SciPy (sparse matrices, root finding for the pool fixed point; also the ODE reference in tests), pandas 3.x, pyarrow, Pydantic v2, PyYAML, the `mcp` package (its bundled FastMCP decorator API), FastAPI, uvicorn, websockets. Plotly.js is vendored into `src/flyonenomics/dashboard/static/`. Test dependencies: pytest, hypothesis. Nothing that needs a GPU, Docker, a database server, or a network connection at run time. Every dependency is pinned in `pyproject.toml` and `uv.lock`; the `uv.lock` SHA-256 is the environment identifier in every manifest.

## 3. Components and interfaces

The data flow. The orchestrator validates an experiment, computes the run-wide input topology, builds the engine once per worker process with that topology, stores the initial state, applies each seed's genotype, stores that, then walks the phases per arm and seed. A probe restores the genotype state, reseeds, initialises the pools at their analytical fixed point for the current slow state, settles to convergence with the arena held, then records: each chunk it reads spike counts, updates the pools and the arena, composes the parameter state, and writes thresholds, gains, and encoder rates back to the engine. A wait advances the slow state analytically. Everything recorded goes to the results store; the live stream, the tool server, and the dashboard read from there. The canonical experiment has `background: false`, `lif.g_inh` 1, and no drive-table pin; background-on runs explicitly pin the development table. (item 47) (item 44)

### 3.1 Engine wrapper (`engine/`)

Responsibilities. Build the Shiu network on v783 (or v630) from the clone's files with a run-wide input topology fixed before the first snapshot; give every neuron its own threshold and gain; provide the upstream-exact Poisson input mode, the extended per-neuron-rate input mode, deterministic spike-list input for tests, threshold silencing, output disconnection, per-connection weight scaling, and per-neuron background drive; step in chunks; expose per-chunk spike counts and an all-neuron 1 ms histogram, the full spike record in engine ticks, and membrane traces for a small set; store and restore state; seed.

Interface (`engine/base.py`; `engine/brian_engine.py` implements it). Every array argument is full length n unless the docstring says it is indexed:

```python
@dataclass
class UpstreamBank:
    idx: np.ndarray                 # int32, in the authoritative source order (not sorted), one PoissonInput per entry
    rate_hz: float                  # immutable; part of the topology

@dataclass
class InputTopology:
    upstream_banks: list[UpstreamBank]   # upstream-exact mode (0.3, level 1); declaration order is construction order
    extended_idx: np.ndarray        # int32, union of every neuron any assay or manipulation will drive by rate, sorted
    spikelist_idx: np.ndarray       # int32, neurons driven by deterministic spike lists (tests), sorted
    trace_idx: np.ndarray           # int32, at most 774 neurons with membrane traces
    background: bool

class Engine(Protocol):
    n: int; n_syn: int
    root_ids: np.ndarray            # int64, index -> root ID, fixed per connectome version
    dt_ms: float                    # 0.1 (0.05 in test 0.2)
    ticks_per_ms: int               # round(1 / dt_ms)

    def build(self, connectome: ConnectomeFiles, params: Params, topology: InputTopology) -> None
        # construction order is fixed (see "Construction order" below); no object is created after build
    def seed(self, seed: int) -> None                              # brian2.seed(seed); seed is uint32
    def set_upstream_active(self, bank: int, active: bool) -> None  # sets .active on that bank's PoissonInputs
    def set_input_rates(self, rate_hz: np.ndarray) -> None          # length len(extended_idx), extended mode
    def set_spike_list(self, idx: np.ndarray, tick: np.ndarray) -> None   # idx subset of spikelist_idx; engine ticks
    def set_threshold(self, v_th_mv: np.ndarray) -> None
    def set_gain(self, gain: np.ndarray) -> None
    def set_background(self, w_bg_mv: np.ndarray) -> None           # 0 = no background for that neuron
    def set_refractory(self, idx: np.ndarray, rfc_ms: np.ndarray) -> None
    def compose_refractory(self) -> None                            # rfc = rfc_base; rfc[targets of active banks] = 0
    def disconnect(self, idx: np.ndarray) -> None                   # zero all outgoing weights of idx
    def set_weight_scale(self, scale: np.ndarray) -> None           # float32, length n_syn, connection file order; 1 = unchanged
    def run_chunk(self, ms: float) -> ChunkResult
    def tick(self) -> int                                           # engine ticks since last build or restore
    def store(self, key: str) -> None                               # full state incl. RNG and monitors
    def restore(self, key: str) -> None                             # restore_random_state=True, then reapplies bank activity
    def spikes(self, since_tick: int) -> SpikeTable                 # all neurons, engine ticks >= since_tick
    def traces(self, since_tick: int) -> TraceTable
    def thresholds_mv(self) -> np.ndarray                            # public readback, mV, length n
    def gains(self) -> np.ndarray                                    # public readback, dimensionless, length n

@dataclass
class ChunkResult:
    tick0: int; tick1: int
    counts: np.ndarray            # int32, length n, spikes per neuron in [tick0, tick1)
    hist_1ms: np.ndarray          # int32, length (tick1 - tick0) // ticks_per_ms, all-neuron spike count per 1 ms bin;
                                  # chunk boundaries are required to fall on 1 ms boundaries

@dataclass
class SpikeTable:
    idx: np.ndarray               # int32
    tick: np.ndarray              # int64 engine ticks; the recorder subtracts the recording start tick
```

The public `thresholds_mv()` and `gains()` readbacks supply the bitwise 3.1b comparison; validation code does not read the private Brian2 group. (item 57)

Model. The Shiu equations with two per-neuron state variables added:

```
dv/dt = (v_0 - v + g) / t_mbr : volt (unless refractory)
dg/dt = -g / tau              : volt (unless refractory)
rfc    : second
v_th_i : volt
gain_i : 1
```

Threshold condition `v > v_th_i`; reset `v = v_rst; g = 0*mV`; refractory `rfc`; integration method `linear`; synapse model `w : volt` with `on_pre = 'g += w * gain_i_post'` and delay `t_dly`; base weights `w = ('Excitatory x Connectivity') * w_syn * scale`. The development drive's `lif.g_inh` multiplies negative connection weights only when background is on, before the initial snapshot; the bare model keeps scale 1. All constants from section 5. At build, `v_th_i = v_th` and `gain_i = 1`. (item 44)

Upstream-exact input mode. For reproduction of the published model, the engine calls the clone's `poi(neu, exc, [], params)` once per declared bank, with `exc` the bank's indices in their declared order: one `PoissonInput` per target with `target_var='v'`, `N=1`, weight `w_syn * f_poi`, rate `bank.rate_hz`, and the target's refractory period set to zero, exactly as `.cache/l5-proof/run_model.py` does. `PoissonInput.rate` is a read-only property in Brian2 2.10.1 and its sampler is built from the rate at construction, so bank rates are immutable topology parameters; a bank is switched on and off through the public `BrianObject.active` flag of its PoissonInput objects (`set_upstream_active`), which `Network.run` honours. `restore` does not touch `active`, so the engine keeps the bank activity it was last told and reapplies it after every `restore`. An experiment that needs the same population at two upstream rates declares two banks. A bank's index order is the authoritative source order of its population: for the sugar GRNs, the order of the notebook's `neu_sugar` literal (the proof run passes that list unsorted; its first five indices on v630 are 65153, 90982, 113421, 114820, 27680), for the bitter GRNs the pickle order, for other populations the registry's explicit-list order. Sorting is never applied to bank indices. The topology derivation collects one bank per distinct (population, rate) pair used by any `upstream`-mode probe in the file, in first-use order.

Construction order, bare reference path (used by test 0.3 and level 1: `upstream_banks` nonempty, `extended_idx` and `spikelist_idx` empty, `background` false, `trace_idx` empty): `brian2.seed(seed)`; `create_model` with the per-neuron threshold and gain variables in the equations (NeuronGroup, Synapses, SpikeMonitor, in the clone's order); `neu.v_threshold = v_th` and `gain_i = 1`; `poi` per bank in declaration order; `Network(neu, syn, spk, *pois)`; `store('initial')`. Test 0.3 then does `restore('initial', restore_random_state=True)` and `run`, as the proof run does, and asserts the spike stream match.

Construction order, extended path (every other topology): the bare reference objects in the same order first (banks included, possibly none), then the background PoissonInput, then the extended PoissonGroup and its Synapses, then the SpikeGeneratorGroup and its Synapses, then the StateMonitor, then `Network(...)` with every object, then `store('initial')`. Whether the extra objects change Brian2's random-number consumption for the bank inputs is not assumed either way: test 0.3b builds the acceptance topology plus the sugar bank and compares against the reference stream; if it fails, the status file records that exact replay requires the bare reference path, and level 1 runs on that path.

Extended input mode. One `PoissonGroup` of size `len(extended_idx)` with a per-neuron `rates` state variable, wired one-to-one by `Synapses` with `on_pre = 'g += w_in'`, `w_in = w_syn * f_poi`. Rates change every chunk; topology never changes. A neuron in more than one drive source receives the sum of rates. Driven neurons keep their refractory period.

Deterministic input. A `SpikeGeneratorGroup` over `spikelist_idx` wired like the extended group; used by tests 0.1 and 0.2 and the pool test 0.5.

Refractory composition. The clone's `poi()` sets every bank target's refractory period to zero at construction (`model.py`, `neu[i].rfc = 0*ms`), so the `initial` and `genotype` snapshots hold zeros for every bank target whether or not its bank is active. The engine therefore treats `rfc` as a composed per-probe array from an immutable base: `rfc_base = t_rfc` for every neuron. On every probe, after `restore` and before settle, the runner calls `engine.set_upstream_active` for each bank and then `engine.compose_refractory()`, which writes `rfc = rfc_base` for all neurons and `rfc = 0` for the targets of the currently active banks. Extended-mode targets and spike-list targets keep `rfc_base`. Overlap rule: a neuron that is a target of an active bank and also has a nonzero extended rate in the same probe gets `rfc = 0` (the upstream rule wins). The default-empty int32 `SettleRecord.upstream_extended_overlap_idx` lists those indices in engine order, `probe-<k>-settle.json` records them, and schema validation warns on the overlap. On the bare reference path with the sugar bank active, the composed array equals the proof run's state, so test 0.3 is unaffected. Bank activity alone is never treated as a mode switch; the pair (activity, composed refractory) is. (item 20)

Bank switching check (test 1.0). On the bare reference path with two banks (sugar at 150 Hz, bitter at 150 Hz): all banks inactive gives zero MN9 spikes over 1 s and `rfc == rfc_base` everywhere; sugar active gives the 1.1 rate with `rfc == 0` exactly on the sugar targets; sugar plus bitter gives the 1.3 reduction; sugar active again after a `restore` gives the same spike stream as the first sugar run. No object is created and no private field is touched.

Mixed-mode check (test 1.0b), an engine-level fixture that bypasses the production seed derivation so that compared probes share one Brian2 seed. One engine is built on the extended path with the sugar bank and the sugar GRNs also in `extended_idx`. The fixture defines two probe procedures with fixed inputs and no settle: E = `restore("initial")`, all banks inactive, `compose_refractory()`, `engine.seed(7)`, extended rates 150 Hz on the sugar GRNs, run 1 s; U = `restore("initial")`, sugar bank active, `compose_refractory()`, `engine.seed(7)`, extended rates zero, run 1 s. The fixture runs the histories E; U,E; E,U,E for the extended target and U; E,U; U,E,U for the upstream target, taking the spike table of the last probe of each history. Required: the three E results are identical to each other; the three U results are identical to each other; after every composition, `rfc` equals `rfc_base` except on the active bank's targets, and equals `rfc_base` everywhere when no bank is active. This checks that mode history leaves nothing behind in the snapshot-restored state. The production per-probe seed derivation of section 3.6 is unchanged and is not exercised here; two production probes at different expanded indices are expected to differ. Whether the extended-path U result equals the bare-path upstream stream is the separate 0.3b question and is recorded, not required.

Silencing is `v_th_i = 1e6 mV` (unreachable), reapplied by the composition rule on every write. `disconnect` exposes the upstream `silence()` operation (zero outgoing weights) under its own name.

Background. One `PoissonInput` targeting `g` of the whole group with `N = n_bg` inputs at rate `r_bg` and per-neuron weight given by the string expression `'w_bg_i'`, a per-neuron state variable in mV. If per-neuron weight strings are not accepted by the installed Brian2, the fallback is one `PoissonInput` per drive group on a contiguous subgroup, with neurons ordered by drive group at build time; `root_ids` reports whatever order was used. `docs/bench.md` records which path was taken.

Chunked stepping. `run_chunk(10)` calls `net.run(10*ms)`, returns the difference of the spike monitor's per-neuron `count` array before and after, and computes `hist_1ms` from the monitor's new spike ticks with `ticks_per_ms` ticks per bin (10 at dt 0.1 ms, 20 at dt 0.05 ms). Ticks come from Brian2's clock (`t / dt`, rounded) minus the tick at the last restore. A 20 s probe yields 20,000 one-millisecond bins.

Two builds. `ConnectomeFiles` carries the completeness and connectivity paths; v783 by default, v630 when the experiment says so. Row counts: v783 has 138,639 completed neurons and 15,091,983 weighted connections; v630 has 127,400 and 14,687,178. The published neuron count of 139,255 for v783 counts proofread neurons (and is the row count of the v2.1.0 annotation file); the model file lists 138,639, so 616 annotated neurons are not in the model, and the registry reports them.

Benchmarks (`scripts/bench.py`). B1: one process, background object present with zero weights on the bare substrate, the `spontaneous` assay with a 200-neuron extended input at 50 Hz, 20 s: wall seconds per brain second `q1`, engine only. B2: the acceptance experiment of section 6.3 restricted to seeds 1 to 4, run at `n_workers = 4`, measuring three wall times separately: `t_build` (process start to `store("initial")`, maximum over workers), `t_probe` (first probe start to last probe end across all workers, one interval on the wall clock), and `t_agg` (aggregation and manifest). The aggregate ratio is `q2 = t_probe / T_B2`, where `T_B2` is the total brain seconds of probes including settle summed over every arm, seed, and probe of the benchmark file. `q2` therefore already contains whatever parallel throughput four workers achieve on this workload; nothing divides it again. B2 also records the mean settle duration `s̄` and the concurrent peak resident memory of all workers. Test 2.5 is a background development entry, unavailable for canonical bare acceptance; section 3.10 budgets from `q2`, `t_build`, and `t_agg`. Escalation: `q1` above 30 goes to Rolf (a Phase 2 engine pulled forward); between 15 and 30 the work continues with the budgets recomputed and test 2.5 recorded failed. (item 47)

### 3.2 Population registry (`registry/`)

Responsibilities. Map root IDs to indices; define named populations from the pinned annotation artefact through declared selectors; define compartments with weighted exposure and innervation; carry the receptor map; report provenance and inventory counts; fail loudly when a required population is missing.

Annotation artefacts, verified for this draft. 2. Candidate sums. For every `CX_DAN_candidates` member j and every compartment c: `S[c, j]` = sum over connectivity rows with presynaptic j of `Connectivity × W[post, c]`, and `T[j]` = sum of `Connectivity` over all rows with presynaptic j. The central-complex fraction is `sum_c S[c, j] / T[j]` over the seven central-complex compartments.
3. Filter, applied once: `CX_DAN` = candidates with fraction at least `cxdan.min_cx_output_fraction` (0.2). Pre-filter and post-filter counts are recorded and listed with every excluded root.
4. Innervation M (n_comp × n), nonzero only for `DAN` and `CX_DAN` columns. Mushroom-body DANs: M[c, j] = 1/k over the k compartments the type innervates, from the type-to-compartment table of Aso et al. 2014 (eLife 3:e04577, the MBON and DAN nomenclature table) as carried into the hemibrain numbering by Li et al. 2020 (eLife 9:e62576); WP2 transcribes that table into the YAML with the citation and records every type it could not place. `CX_DAN`: M[c, j] = S[c, j] / sum_c S[c, j] over the seven central-complex compartments. Equal splitting for mushroom-body DANs is a placeholder.
5. Autoreceptor rows of W, added last: every `DAN` and `CX_DAN` member gets W[j, ·] = M[·, j] (exposure to its own innervated compartments). Candidates that failed the filter keep a zero row.

Unmapped neurons have zero rows; `exposed_mask` is False for them and section 3.4 masks their modulation to identity. The manifest reports the unmapped fraction.

### 3.4 Neuromodulation, layers A and C (`neuromod/`)

Responsibilities. Own the composed parameter state of every neuron; hold one dopamine concentration per compartment; raise it with DAN spikes; clear it with transporter kinetics plus a non-transporter clearance; convert compartment dopamine into per-neuron gain and threshold via exposure weights and the receptor map, as an absolute effect of the dopamine level; hold the pools clamped for calibration; hold the drug state and advance it analytically during waits; initialise pools at their fixed point and settle to convergence.

Parameter state (`neuromod/state.py`). Immutable base arrays and persistent layers, composed in a fixed order on every write. Arrays are length n unless stated:

```
base:      v_th0 = v_th, gain0 = 1, Vmax0_c, Km0_c, k_ns0, rel0 = 1
genotype:  dV_geno (mV, additive, default 0), g_geno (multiplicative, default 1),
           silenced (bool), disconnected (bool, applied once via engine.disconnect),
           dat_geno_c (multiplicative on Vmax, default 1), rel_geno (scalar, default 1),
           r1, r2, rq (persistent copies of the map, scaled by scale_receptor)
drug:      C_b[drug] (µM brain), rel_drug (scalar), Km_eff_c
dopamine:  dV_da (mV), g_da (multiplicative); clamped (bool, pools held at DA_ref, calibration only)

composition:
  v_th_i   = clip(v_th0 + dV_geno_i + dV_da_i, vth_clip);  v_th_i = silence_vth where silenced_i
  gain_i   = clip(gain0 * g_geno_i * g_da_i, gain_clip)
  rel      = rel0 * rel_geno * rel_drug
  Vmax_c   = Vmax0_c * dat_geno_c
  Km_eff_c = Km0_c * (1 + C_b[mph] / Ki_mph)
```

Layer flags and their identity behaviour, enforced at validation and in `compose()`:

- `dopamine_A = false`: `dV_da = 0`, `g_da = 1` at every dopamine level, so the tonic contribution is removed with the evoked one; pools still run and are recorded; `scale_receptor` manipulations are rejected at validation ("layer off"). An A-off run differs from the canonical A-on bare substrate and cannot borrow its matching-layers behaviour entries. A development background drive calibrated with A on also has different rates when A is off. (item 47) (item 54)
- `transporter_C = false`: `dat_geno_c = 1`, `Km_eff_c = Km0_c`, `rel_drug = 1`, no pharmacokinetics; `dose` phases with any drug other than `vehicle`, and `scale_dat` and `scale_release` manipulations, are rejected at validation. The pools then clear with the base transporter and non-transporter terms.
- `dan_fast_synapses = "disconnect"`: `engine.disconnect` on `DAN` plus `CX_DAN` at genotype application.
- Combinations: any of the eight combinations of the three flags is valid; test 0.7 checks each against the arrays this section specifies.

Pools (`neuromod/pools.py`). State per compartment c: `DA_c` (µM). Per chunk of length Δ = 0.01 s, with `s` the length-n spike-count vector and `M` the innervation matrix:

```
release_c = rel * (S_c * f_retained,c * Δ + alpha_c * (M @ s)_c)
clear_c   = Vmax_c * DA_c / (Km_eff_c + DA_c) + k_ns * DA_c           (at the start of the chunk)
DA_c     <- max(0, DA_c + release_c - clear_c * Δ)
```

for innervated compartments (nonzero M row). On the bare substrate `S_c = DA_ref × (Vmax0_c / (Km0_c + DA_ref) + k_ns0)` in µM/s is the constant tonic source and `alpha_c` scales phasic spikes. `f_retained,c` is the retained fraction of compartment c's M weight under DAN silencing, assuming uniform contribution; it is 1 without silencing and 0 when all its DANs are silenced. The source enters `fixed_point()` as well as the chunk update; `rel`, transporter parameters, and drugs act through the equations, so fumin and methylphenidate can raise the fixed point above `DA_ref` without tonic spikes. This is the provisional Phase 1 tonic-source rule, recorded as `da.tonic_source` in K2 and every manifest. `k_ns` is a first-order non-transporter clearance with a placeholder value; it gives fumin a finite steady state. Uninnervated compartments hold `DA_ref` constant and are listed in the manifest. Test 0.5 compares the integrator with SciPy on a fixed spike train. (item 51) (item 53)

Exposure and receptor effect, absolute formulation (resolution 10, section 10). `DA_i = (W @ DA)_i` for exposed neurons. With dissociation constants `Kd_1`, `Kd_2`:

```
occ_k_i  = DA_i / (DA_i + Kd_k)
o_k_i    = occ_k_i * exposed_i
g_da_i   = 1 + gamma_D1 * r1_i * o_1_i - gamma_D2 * r2_i * o_2_i
dV_da_i  = -dV_D1 * r1_i * o_1_i + dV_D2 * r2_i * o_2_i
```

The effect is a function of the compartment's dopamine level itself, not of its deviation from a reference; it is identity only where dopamine, exposure, or receptor density is zero. The `exposed_i` mask makes modulation identity where there is no exposure. `DA_ref` is the wild-type tonic target, the same for every compartment; on the bare substrate the constant source supplies it without spontaneous DAN firing. A qualified resting substrate can instead derive release from measured DAN rates and tune K1 with the pools clamped there. The tonic arrays are the effect evaluated at `DA_i = DA_ref` for every exposed neuron, with `occ_k_ref = DA_ref / (DA_ref + Kd_k)`. (item 47) (item 51)

```
g_tonic_i  = 1 + gamma_D1 * r1_i * occ_1_ref * exposed_i - gamma_D2 * r2_i * occ_2_ref * exposed_i
dV_tonic_i = -dV_D1 * r1_i * occ_1_ref * exposed_i + dV_D2 * r2_i * occ_2_ref * exposed_i
v_th_tonic = clip(v_th0 + dV_tonic, vth_clip);  gain_tonic = clip(gain0 * g_tonic, gain_clip)
```

With the section 5 values `occ_1_ref` is about 0.02 and `occ_2_ref` about 0.29, so the tonic D2 effect is the larger one: an exposed neuron with `r2 = 1` has gain about 9 percent below 1 and threshold about 0.6 mV above `v_th`, and one with `r1 = 1` has gain about 0.6 percent above 1 and threshold about 0.03 mV below. The canonical bare model receives this receptor effect from the tonic source, without a calibrated background drive. Removing a receptor removes its tonic and evoked terms, so `dop1r1_null` differs from wild type wherever `r1` and exposure are nonzero. Placeholder receptor densities shape both effects. The formulation name `absolute` is in every manifest. (item 47) (item 51)

Fixed point and calibration K2 on the bare substrate. Measured `R_c` is 0 weighted spikes/s in all 37 compartments over all three seeds; every compartment is under `R_min`, receives `alpha_c = alpha_max = 0.1 µM` per weighted spike, and has `S_c = 0.00267 µM/s`. The phasic scale is therefore the placeholder `alpha_max`, not a rate-derived calibration. The record remains `qualified: false` until bare-substrate Q passes 3.1b, 1.4, and 2.2 on free pools, after which it is frozen `qualified: true`. Every results document names this placeholder alongside the deferred background-target limitation. (item 48) (item 51) (item 56)

Derived-rate form for a substrate with a qualified resting state. With `R_c` measured under a clamped, K1-calibrated drive, `alpha_c = DA_ref × (Vmax0_c / (Km0_c + DA_ref) + k_ns0) / R_c` when `R_c ≥ R_min`; under-innervated compartments use `alpha_max`. This form requires a subsequent free-pool Q because coupled DAN rates can change. For either substrate, `fixed_point()` solves `Vmax_c × x / (Km_eff_c + x) + k_ns × x = rel × (S_c + alpha_c × R_c) × f_retained,c` for the non-negative root, with the source term omitted in the derived-rate form. For a non-wild-type state, `fixed_point()` reuses the recorded wild-type K2 `R_c` and ignores rate changes induced by that state; `reset_fast()` is followed by settle. Uniform tonic baseline and uniform silencing contribution are placeholders. Transporter constants from Vickrey, Xiao, and Venton 2013 are larval, diffusion-corrected measurements whose transfer to adult neuropil is an assumption. (item 48) (item 51) (item 53)

Reset and settle (`neuromod/state.py`). `reset_fast()` sets every innervated `DA_c` to `fixed_point()` for the current composed parameters (so a fumin or drugged probe starts near its own steady state rather than at `DA_ref`) and then composes `dV_da`, `g_da` from those concentrations, so the first chunk already carries the tonic effect of the probe's own state; in the clamped calibration state it sets every compartment to `DA_ref` and `on_chunk()` leaves it there. `settle()` then runs unrecorded chunks with the stimulus on and the arena held. Every `settle.window_s` it compares the last window with the one before: converged when, over innervated compartments, the maximum absolute change in mean `DA_c` is under `settle.tol_abs_da` and the maximum relative change under `settle.tol_rel_da`, and the mean rate of each recorded population changes by under `settle.tol_rate` relative or under `settle.tol_abs_rate` absolute. Minimum `settle.min_s`, maximum `settle.max_s`. The settle duration and the convergence flag are recorded per probe; an unconverged settle marks the run "unsettled", and an unsettled run fails acceptance clause 3. On the bare substrate, `R_c == 0` without DAN silencing still yields the `DA_ref` fixed point from `S_c`; full DAN silencing sets `f_retained,c = 0` and the fixed point to 0 µM, while partial silencing scales the tonic term by the retained M fraction. (item 51) (item 53)

Layer C drugs (`neuromod/drugs.py`). Every parameter names its compartment and unit:

- `vehicle`: no-op with the same phase structure.
- `methylphenidate`: competitive DAT block, `Ki_mph` in brain µM, enters `Km_eff_c`.
- `3-iodotyrosine`: release reduction, `rel_drug = 1 / (1 + C_b[3iy] / EC50_3iy)`, `EC50_3iy` in brain µM.
- `amphetamine`, `atomoxetine`, `caffeine`, `cocaine`: recognised names, rejected at validation with `NotImplementedInPhase1`.

Effects combine multiplicatively on release and on Vmax; methylphenidate acts only on Km. Two supported drugs may be active at once and combine by these rules only.

Genotype hooks: `fumin` sets `dat_geno_c = 0`; `dop1r1_null` sets `r1_i = 0`, which removes the tonic and the evoked Dop1R1 terms alike; `dopamine_depleted` sets `rel_geno = 0.5`. Generic manipulations write the corresponding layer.

Pharmacokinetics (`neuromod/pk.py`), one brain compartment per drug; `C_food` in mM while a dose phase is active; `C_b` in µM; `kappa` in brain µM per food µM:

```
exposure on:   dC_b/dt = k_a * (kappa * 1000 * C_food - C_b)
exposure off:  dC_b/dt = -k_e * C_b
```

Closed-form solutions; `advance(hours)` uses them. `kappa` is a declared free parameter, printed in every summary that used a drug. During a probe `C_b` is held constant.

Brain clock and slow-state approximation. The runner keeps one brain clock `t_brain_s` per arm and seed, advanced by every phase: `wait` by its hours, `probe` by its settle duration plus its recorded duration, `dose` and `washout` by zero. Drug concentrations are integrated over every advance, including probes (held constant within a probe at the value at probe start, then advanced by the probe's duration afterwards; the error is under one percent for a 30 s probe against hour-scale constants and is stated). The approximation, recorded in every manifest as `slow_state: "phase1-drug-only"`: only drug concentrations carry across phases; neural state, pools, arena state, filters, and monitors are reinitialised at every probe start. There is no receptor kinetics, no plasticity, and no neural memory across phases; a `repeat` block shows only pharmacokinetic differences between iterations, and the summary of any experiment with a `repeat` says so.

Conventions. Arena frame: origin at the platform centre, azimuth measured clockwise from the direction of stripe A, in degrees, wrapped to (−180, 180]. The reference data's stripes sit at 90 and −90 in its own frame; the ingester rotates so that stripe A is at 0. Heading h uses the arena frame. A stimulus azimuth as seen from the fly is `wrap(az_arena − h)`. Stripe A and B are vertical bars on the wall of radius `R_wall`, centred at arena azimuths 0 and 180, of width `stripe_width`; from position p each bar's centre azimuth and angular width are computed from its two edge points on the wall (exact, no small-angle approximation).

Arena (`behaviour/arena.py`). Platform of radius `R_platform` = 58.5 mm. State: position p (mm), heading h (deg), smoothed rates `r_L`, `r_R`, and the probe's `behaviour` stream. `reset(stream)` sets p = (0, 0), h = 0, rates 0. During settle the arena is held at that state with the stimulus rendered for it; the loop starts moving at recording tick 0. Each chunk of length Δ = 0.01 s, with `xi ~ N(0,1)` from the stream:

```
omega   = sign_steer * K_steer * (r_R - r_L)              deg/s
h      <- wrap(h + omega * Δ + sigma_h * sqrt(Δ) * xi)    sigma_h in deg/sqrt(s)
p      <- p + v_fwd * Δ * (sin h, cos h)                   v_fwd in mm/s, constant in Phase 1
if |p| >= R_platform - edge_margin:
    p <- p * (R_platform - edge_margin) / |p|
    h <- wrap(h + 180 + sigma_edge * xi_edge)              one draw per edge event
```

`sign_steer` is +1 by the Rayshubskiy 2024 convention (DNa02 activity is higher ipsilateral to the turn, so right-minus-left drives clockwise turning) and may be set to −1 once by the sign check in section 7 before K3; it is stored in `behaviour-v0.1.yaml`. `v_fwd` is constant in Phase 1, set at ingestion to 15.25 mm/s: the median across calibration flies of each fly's median positive post-freeze 10 Hz step speed. The published CeTrAn `median_speed` is recorded alongside this derivation in `behaviour-dev.yaml` and is not used. The edge rule stands in for the turn a real fly makes at the water moat. Two controls isolate arena mechanics from the brain: `stripes: false` and `encoder: "off"`. (item 37)

Steering rates. `r_L`, `r_R` are the mean per-neuron rates of `steering_L` and `steering_R` from chunk counts, smoothed with an exponential filter of time constant `tau_rate`, reset per probe.

Visual encoder (`behaviour/encoder.py`). Injection site: `TuBu`, both sides. Assumption, stated as such: each TuBu neuron on side s is assigned a preferred azimuth on an even grid across the ipsilateral hemifield from `pref_range[0]` to `pref_range[1]`, by ascending root ID within the side; the encoder-permutation detector (section 9.2) bounds the influence of this choice. The rate of neuron i is:

```
rate_i = min(r_vis_max, r_vis_max * Σ_j contrast_j * exp(-angdiff(az_j, pref_i)^2 / (2 sigma_vis^2)))
```

The distractor is a third bar at a fixed arena azimuth whose contrast switches between 0 and `distractor_contrast` at `flicker_hz` with 50 percent duty, present as one episode from `onset_s` for `duration_s` of recording time. Rates are written every chunk with `set_input_rates`. Buridan accepts per-probe `inject_at: "ER"` to use ring neurons; `open_loop_steering` always uses `vis.inject_at` from `Params` as its fixed calibration and sign-check population. (item 39)

Buridan protocol (`behaviour/buridan.py`). A probe of `duration_s` (default 20 s) after settle. Records per chunk: recording tick, x, y, h, omega, r_L, r_R, and per stimulus its arena azimuth, fly-relative azimuth, angular width, and contrast. The `open_loop_steering` assay holds the fly at the centre with h = 0, presents a single stripe at fixed fly-relative azimuths from −150 to +150 in 30 degree steps, each for `transition_s` (excluded) plus `dwell_s` (recorded), 33 s in total for the default 11 azimuths, and records mean `r_R − r_L` and mean `omega` per azimuth: the steering tuning curve. The synthetic sign procedure is `4.1-procedure`; the real sign check and 4.1/4.2 conclusions require matching bare-substrate layers. (item 42)

Metrics (`behaviour/metrics.py`). Input: a trajectory table `t_s, x_mm, y_mm, segment` in the arena frame at any sampling rate (`segment` is the `burst` column for real data and constant for model data), a geometry record (platform radius, wall radius, stripe azimuths), and optionally a stimulus-episode table (distractor onsets and durations, model only). No heading is used, so real and model trajectories are scored identically. The definitions are CeTrAn v.4's, transcribed from the pinned files; the fixation index, activity, and switch rate are this project's additions computed on the same steps.

- Resampling. Each segment is linearly interpolated onto a 10 Hz grid (`resample_hz`) starting at the first multiple of 0.1 s after the segment's first sample and ending at its last sample (CeTrAn `set.sampling.rate`). Segments shorter than two grid points are dropped.
- Freeze filter, a literal transcription of the pinned `mindistkeep3` (`utils.r`), applied per segment to the grid points `P[1..n]`. Let `d[i]` be the distance from `P[i]` to `P[i+1]` (`d[n]` undefined), `kept[1] = 1`, and `lo = step_min_mm` (0.8, the slider default 8 over 10), `hi = step_max_mm` (70). For `i = 2..n`: if `d[i-1] < lo` or `d[i-1] > hi`, then `kept[i] = kept[i-1]`, and additionally, only when `d[i-1] < lo` and `i < n`, `d[i]` is replaced by the distance from `P[i+1]` to `P[kept[i]]`; otherwise `kept[i] = i`. The output point at slot `i` is `P[kept[i]]`. Two consequences the fixtures cover: after a below-minimum step the next test measures from the last kept point, so slow drift accumulates until it exceeds `lo`; after an above-maximum step the next test uses the original step `d[i]` (not the distance from the kept point), so the one-dimensional sequence 0, 100, 101, 0 with these thresholds yields kept slots 0, 0, 101, 101. This is the rule for both modes; no corrected filter is used in Phase 1. After it, a step is the displacement between consecutive output points; a step of zero length has no direction and is "undefined".
- Step direction: `atan2` of the step displacement. Target azimuths: from the step's start point to each stripe's centre on the wall at radius `R_wall`. Deviation of a defined step: the smaller of the two absolute wrapped differences between the step direction and the two target azimuths, in degrees.
- Stripe deviation: the median of the deviations over the defined steps of the observation unit (CeTrAn `angledev.r`), degrees. Fixation index FI: fraction of defined steps with deviation under `fix_angle`. Both report their denominator, the count of defined steps.
- Walks (CeTrAn `c.nwalks`). Stripe area k is the set of points p with `p · u_k > walk_area_fraction × R_platform`, where `u_k` is the unit vector toward stripe k. Within a segment, walking the output points in order: a walk is counted each time the trajectory enters a stripe area that is not the last stripe area it entered in that segment; the first entry in each segment is not counted. The "last entered" state, the between-areas flag, and the first-entry flag are reset at every segment start (CeTrAn resets them per burst) and at every observation-unit start; a traversal that falls in a gap between segments is never counted. A segment boundary inside a window splits the window's walk state likewise.
- Activity: defined steps over all steps of the unit.
- Distractor switch rate (model only): one window per distractor episode, from its onset for `switch_window_s`; the window is valid if at least half its steps are defined; a switch is scored if the circular mean direction of the defined steps in the window's second half is closer to the distractor's azimuth (from the position at onset) than that of the first half by more than `switch_angle`; the rate is switches over valid windows, and the count of invalid windows is reported.
- Observation units, two modes. Full-record mode: the whole recording, every segment, one value per fly; used only by test 4.0b to compare with CeTrAn. Window mode: the 10 Hz record is cut into consecutive non-overlapping 20 s windows (`buridan.duration_s`) from the recording's start; each window is scored as a unit; a fly's value is the median over windows whose defined-step fraction is at least `min_window_fraction`. A model seed's probe is one window. K3, 4.2, 4.3, and every model-versus-reference comparison use window mode on both sides. Reference distributions are over fly values.

Verification of the metric against the reference. Test 4.0b runs full-record mode over every reference fly and compares with the `stripe_deviation` and `number_of_walks` columns of `output _table.csv`, once with `step_min_mm` 0.8 and once with 0.6 (the two defaults found in the pinned source); the threshold that matches more flies is written into `params-v0.1.yaml` with the match counts, and the test passes if at least 90 percent of the 128 flies are within `cetran_tol_deg` and `cetran_tol_walks`. Residual differences are recorded. The definitions above are normative for Phase 1; no later revision is needed to fix them.

Brembs ingestion (`behaviour/brembs.py`). Reads every `*.dat` with its `*.xml`, converts pixels to mm with the file's own scale and centre, rotates stripes to the arena frame, keeps the `burst` column as the segment id, resamples nothing (the metrics function does), and produces one trajectory table per fly plus a fly table (label, sub-strain, batch, machine, duration, frame count, segment count). Files without an XML header or with a duration other than 300 s are excluded and listed. Output `data/brembs-metrics.json` (per-fly values, denominators, and `shared_raw_file` for the two published rows from `CSbvs_7.dat`) and `data/brembs-split.json` (section 7). (item 36)

Calibration K3 (`behaviour/buridan.py: calibrate()`), run by `scripts/calibrate.py` after K2, bare-substrate Q, and the sign check, with `background: false`, A and C on, wild type, vehicle, and window mode on both sides. The development layers-off runs yield TuBu spikes but no steering spikes; flat tuning, equal K3/4.2 metrics, and high initial-condition fixation are development findings only. The resolved selectors are TuBu 150, ER 278, EPG 51, and two steering neurons per side; a 500 Hz LAL input gives steering rates of 87 Hz/neuron left and 63.25 Hz/neuron right. ### 3.6 Experiment schema and orchestrator (`schema/`, `orchestrator/`)

The schema is in section 6. The orchestrator:

```python
def run(experiment: Experiment, store: ResultsStore, n_workers: int) -> RunId
```

Random streams (`orchestrator/seeds.py`). Fixed component identifiers: `ENGINE = 1, BEHAVIOUR = 2, ENCODER = 3, JITTER = 4, LIVE = 5, ANALYSIS = 6`. For experiment seed `S`, seed id `s`, and expanded probe index `k` (the index of the probe in the arm's expanded phase list, counting from 0):

```python
def stream(S: int, s: int, k: int, component: int) -> np.random.Generator:
    ss = np.random.SeedSequence(S, spawn_key=(s, k, component))
    return np.random.default_rng(ss)

def brian_seed(S: int, s: int, k: int) -> int:
    ss = np.random.SeedSequence(S, spawn_key=(s, k, ENGINE))
    return int(ss.generate_state(1, dtype=np.uint32)[0])       # in [0, 2**32)
```

Arms are not part of the key: two arms with the same `S`, `s`, and `k` use the same streams, which is what makes them paired. The `ANALYSIS` stream uses `k = 0` and drives bootstraps; the `LIVE` stream drives spike sampling so that recording options never touch experiment randomness. Test 0.8 verifies invariance of every recorded table to arm order, `n_workers`, and `live` on or off.

Per worker process: `build` once with the run-wide topology; `store("initial")`. Per seed: `restore("initial")`; construct registry, neuromod, and behaviour objects; `apply_genotype`; `store("genotype")`. Per probe `k`, in order: `restore("genotype")`; `engine.seed(brian_seed(S, s, k))`; `engine.set_upstream_active` for every bank (active only if this probe uses it) and `engine.compose_refractory()`; behaviour and encoder objects get `stream(S, s, k, ·)`; `arena.reset`; filters reset; `neuromod.reset_fast()`; `compose` and write; the assay sets input rates for the held arena; `settle`; `record_start_tick = engine.tick()`; then the chunk loop:

```
for each chunk:
    rates = encoder.rates(arena.view(), recording_time)
    engine.set_input_rates(rates)
    res = engine.run_chunk(chunk_ms)
    neuromod.on_chunk(res.counts, chunk_s)
    p = neuromod.compose(); engine.set_threshold(p.v_th); engine.set_gain(p.gain)
    arena.step(res.counts, chunk_s)
    recorder.chunk(res, neuromod.state(), arena.state(), record_start_tick)
    live.maybe_emit(...)
    if cancel requested: finalise as cancelled and stop
after the probe: neuromod.advance_slow(settle_s + duration_s); t_brain_s += settle_s + duration_s
```

`dose`, `washout`, `wait` call the slow-state functions, advance `t_brain_s`, and append a row to `slow-state.parquet`. `repeat` expands to its body n times with the given spacing as a `wait`. Probe tables are written at the end of each probe; `status.json` at each phase boundary. After the last seed of every arm, the aggregator computes metrics and the manifest.

Workers (`orchestrator/workers.py`). Seeds are distributed across `n_workers` processes; each holds one built network. Each worker owns its `arm-<a>/seed-<s>/` directories; the parent aggregates and writes the index. Lifecycle states in `status.json`: `queued`, `building`, `running` (arm, seed, phase index, brain time, wall time, estimated remaining), `aggregating`, `done`, `failed` (with traceback), `cancelled`. Every write of `status.json` and `manifest.json` is atomic (temporary file in the same directory, then rename). The manifest is written last. Cancellation: the presence of `runs/<id>/CANCEL` is checked at every chunk and every phase boundary.

### 3.7 Tool server (`server/mcp_server.py`)

A stdio MCP server built with the `mcp` package's FastMCP decorator API, started with `uv run flyonenomics-mcp`, registered in Claude Code's MCP settings per `docs/mcp-setup.md`. The settings entry passes `FLYONENOMICS_RUNS_DIR` and `FLYONENOMICS_CACHE_DIR`; when unset, the server resolves them to repository `runs/` and `.cache/` and reports the resolved paths in `describe_lab`. Tools return JSON. (item 33)

- `describe_lab()`: substrate versions, layers and their validation status, assays, drugs, named genotypes, the slow-state approximation, the list of what the map leaves out (feasibility section 4, verbatim), and the free parameters in force.
- `list_populations()`, `describe_population(name)`, `list_compartments()`, `resolve_population(spec)`.
- `get_schema()`, `example_experiments()`.
- `validate_experiment(experiment)`: schema validation plus resolution of every population and drug and the matched-arm check; returns errors or the resolved experiment with counts.
- `run_experiment(experiment, n_workers=4)`: validates, registers the run in the index as `queued`, starts the parent process detached, returns `run_id`.
- `run_status(run_id)`, `cancel_run(run_id)`.
- `get_results(run_id, what, arm=None, seed=None, probe=None)`: `what` in {summary, metrics, provenance, slow_state, dopamine, receptors, drug, arena, rates, spikes, popcount, index, live}; each stored per-probe and per-seed table has the same path/rows/columns/preview response shape. Large tables return paths plus bounded previews; `live` returns parsed events. (item 31) (item 33)
- `list_runs(filter)`: indexed runs matching the filter.
- `compare_runs(run_ids, metric)`: side-by-side tables with seeds and paired differences where runs share `S`, seed lists, and arms. With any mismatch, the comparison returns unpaired per-arm mean, standard deviation, n, and per-seed values, `paired: false` with a reason, and no difference interval. More than two run IDs compare the first two and name them. (item 28) (item 33)
- `validation_status()`.

### 3.10 Wall-time budgets

Workloads. Acceptance file: two arms, ten seeds, two probes each of settle plus 20 s. Experiment set: eight arms (four genotypes × vehicle and drug), ten seeds, same probes, plus the two control files (two arms each, ten seeds, one probe) and the ablation file (eight arms, ten seeds, one probe). Open-loop version: probes of settle plus 33 s.

Budget rule. `T` is the total brain seconds of probes in a file including settle, summed over every arm, seed, and probe. With `q2`, `t_build`, and `t_agg` from benchmark B2 (section 3.1, aggregate convention: wall seconds of the probe phase divided by the total brain seconds it covered, at four workers), one execution's budget is `budget_margin × q2 × T + t_build + t_agg`, with `budget_margin` 1.25. Nothing divides by a worker count: `q2` was measured with the workers running. Worked example with the numbers B2 will replace: `s̄` 3 s, so the benchmark file (two arms, four seeds, two probes) has `T_B2 = 2 × 4 × 2 × 23 = 368` brain s; if its probe phase took 900 wall s, `q2 = 2.45`; the acceptance file has `T = 2 × 10 × 2 × 23 = 920` brain s and a budget of `1.25 × 2.45 × 920 = 2,817` s, about 47 minutes, plus `t_build` and `t_agg`; applying the rule back to the benchmark file itself gives `1.25 × 900 = 1,125` s, which covers its measured 900 s. The acceptance validation as a whole is two executions (clause 6) plus the validation suites of section 7, and `docs/bench.md` reports each part's measured time and budget. The open-loop fallback has its own `T` and its own budget line. Memory: B2 reports the concurrent peak resident memory; if it exceeds 20 GB at four workers, `n_workers` drops to three and B2 is rerun. B1's `q1` is an engine-only figure and is never used to infer speedup.

### 6.1 Fields

Pydantic v2 models in `schema/experiment.py` with `extra = "forbid"`; JSON on disk. Top level `Experiment`:

- `schema_version`: "1.2".
- `name`: string matching `^[a-z0-9][a-z0-9-]{0,63}$`. `description`: string, optional.
- `seed`: integer `S` in [0, 2^32). `seeds`: list of distinct integers `s` in [0, 2^32), at least one.
- `substrate`: `connectome_version` ("783" default or "630"), `annotation_version`, `receptor_map_version`, `params_version`, `drive_version`, `dopamine_version`, `behaviour_version`. Omitted fields take the current defaults and the resolved values are written back.
- `layers`: `background` (bool, default false on the canonical bare substrate), `dopamine_A` (bool, default true), `transporter_C` (bool, default true), `dan_fast_synapses` ("retain" default or "disconnect"), `receptor_kinetics_B` (must be false), `learning_D` (must be false). (item 47)
- `arms`: list of one or more `Arm {label, genotype, protocol, layers?}`; `label` matches `^[a-z0-9][a-z0-9-]{0,31}$` and is unique within the experiment. An arm may override only `dopamine_A` and `dan_fast_synapses`; when any arm overrides, `comparison` must be `"ablation"`. Arms share `seed`, `seeds`, `record`, and `substrate`. Genotype and protocol belong to arms only.
- `comparison`: `"paired"` (default; arms differ only in genotype and drug names) or `"ablation"` (arms may also differ in the overridable layer flags).
- `genotype`: `named` (one of `wild_type`, `fumin`, `dop1r1_null`, `dopamine_depleted`) plus `manipulations`, a list of: `silence {population}`; `disconnect {population}`; `activate {population, rate_hz}`; `shift_threshold {population, delta_mv}`; `scale_gain {population, factor}`; `scale_receptor {receptor: D1|D2|Dq, population|"all", factor}`; `scale_dat {compartments|"all", factor}`; `scale_release {factor}`. Numeric domains: `rate_hz` in [0, 1000]; `delta_mv` in [−20, 20]; `factor` in [0, 10]; all finite.
- `protocol`: ordered list of phases:
  - `probe {assay, duration_s, label, params}`; `assay` in {`buridan`, `open_loop_steering`, `sugar_reflex`, `spontaneous`}; `duration_s` a positive multiple of 0.01 up to 120; Buridan params `stripes` bool, `encoder` "on" or "off", `distractor {azimuth, flicker_hz, contrast, onset_s, duration_s} | null`, `inject_at`; open_loop params `azimuths` optional; sugar_reflex params `population`, `rate_hz`, `mode` ("upstream" or "extended"); spontaneous params `input {population, rate_hz} | null`.
  - `dose {drug, c_food_mm}` with `c_food_mm` in (0, 100]; `washout {drug}`; `wait {hours}` with hours in (0, 240]; `repeat {n, spacing_hours, body}` with n in [2, 20], no nesting.
- `record`: `spikes` ("all" or population names), `rates` (population names), `dopamine`, `receptors`, `drug`, `arena`, `popcount` (bool, default true), `rate_bin_ms`, `live`.
- `meta`: free dictionary.

Validation rules. At least one probe per arm; `washout` must follow a `dose` of the same drug in the arm; drug names must be supported (`vehicle`, `methylphenidate`, `3-iodotyrosine`); every population resolves to at least one neuron; `connectome_version` "630" remains schema-valid but the runner refuses it before registry construction because its v630 registry view is deferred; v630 engine-only reproduction tests remain available; manipulations and doses that need an off layer are rejected (section 3.4); arms are matched: after expansion and resolution, the phase lists must be identical in type, order, durations, assay, and every assay parameter, with only `genotype`, drug names, and (for ablation) the overridable flags allowed to differ, and the validator prints the first differing field otherwise; experiments with `repeat` get the pharmacokinetics-only note. A dose series places three sequential levels within each arm, uses 100 h analytic washouts as PK resets, and matches `c_food_mm` phase by phase while pairing vehicle and drug arms. (item 22) (item 49)

## 7. Validation

`scripts/run_validation.py` runs every test below and writes `validation/status.json`: for each test its identifier, category, outcome (`passed`, `failed`, `recorded` for calibration, sensitivity, and prediction entries, `unavailable` when its data are absent, `stale` when its binding no longer matches, `unqualified` when it depends on an enabled drive table or `dopamine-v0.1.yaml` whose record says `qualified: false`), the measured values, and two blocks. An `unqualified` entry never satisfies a component-map entry. A bare run with `background: false` does not depend on a drive record. (item 47) (item 48)

The identity block records what was executed: code commit, `uv.lock` hash, `data/provenance.json` hash, every `data/*-v0.1.yaml` version, the connectome version, the layer flags in force, the hash of the canonical fixture the test ran (a protocol file under `data/experiments/` or `tests/fixtures/`, named in the test's definition), the assay, the machine identifier (`sysctl hw.model` and chip), and the date.

The compatibility rule decides whether a stored result may be used by a given run. Every test declares a configuration class in `validation/*.py`:

- `canonical`: the test runs its own fixed fixture (0.1 to 0.5, 0.7, 0.8, 1.0 to 1.4, 2.1 to 2.5 where a qualified background exists, 3.1 to 3.9 except final 3.8, 4.0, 4.0b, `4.1-procedure`, the registry checks, K1 and K2, and Q). Its result is valid for a run when the run's code commit, `uv.lock` hash, provenance hash, and the data-file versions the test declares as dependencies equal the identity block's, and the stored fixture hash equals the hash of the fixture as it now exists. Layer flags and the run's protocol are not compared; the fixture's own flags (for example background off in 1.1, the bare reference path in 0.3, A and C on with free pools and background off in bare-substrate 1.4, 2.2, and 3.x) are part of the test's definition. (item 42) (item 47) (item 48)
- `matching-layers`: the test's conclusion is about a layer configuration (real 4.1, 4.2, 4.3, K3, the sign check, final 3.8, 4.4 to 4.8). Valid under the canonical rule and additionally only when the run's resolved layer flags (`background`, `dopamine_A`, `transporter_C`, `dan_fast_synapses`) equal the identity block's flags. K3, the sign check, and 4.2 to 4.8 are defined with bare-substrate `background: false`, A and C on, so a layers-off behavioural result is never valid for a layers-on run, and a run with any layer off cannot claim "level 4 closed-loop passed" unless matching-layers 4.1, 4.2, and 4.3 exist for exactly its flags. Real 4.1 and 4.2 stay unavailable until WP9 measures them after bare-substrate K3; the synthetic `4.1-procedure` is canonical and does not qualify the behaviour layer. (item 6) (item 42) (item 47)
- `run-bound`: the test is about the specific experiment (0.6, `validate_run`, the detectors). Valid only when the stored protocol hash equals the run's validated experiment hash.
- `development`: a stub or provisional execution (3.8-dev, WP6's provisional K3, any test run with a stub component or `drive-dev.yaml`). Recorded in `validation/status.json` with the stub named, and never valid for any component-map entry. Stubbed 0.6-lite and 0.8 remain development with their intended classes recorded; after stubs are replaced, 0.6-lite has one run-bound entry per experiment file and 0.8 becomes canonical. (item 21)

Manifests quote entries by identifier and identity hash and mark each `valid` or `stale` under this rule; `stale` entries never satisfy the component map. The server and dashboard derive each on-layer flag status from these identities: `valid` when every canonical or matching-layers entry recorded with that flag on is compatible and passed or recorded; `stale` when any such entry is stale or failed; `absent` when no such entry exists or its component remains a stub. A background-off run does not need a drive-table identity. Test 0.9 (verification) exercises the rule: a stored 0.3 result on the bare v630 path is valid for the layers-on v783 acceptance run; a stored 4.3 result with `dopamine_A = false` is stale for it; a stored 0.6 result for a different experiment file is stale for it; a change of `uv.lock` makes every entry stale. ### 9.2 Artefact detectors (`validation/artefacts.py`)

Each detector writes its result to the manifest as `tripped`, `clear`, `unknown`, or `not run`. A tripped detector marks the run "artefact-flagged" in the index and on the dashboard.

- Input completeness (every run, cached per registry version). For every population used, the fraction of its neurons' input synapses that come from neurons in the model: numerator the sum of `Connectivity` over incoming rows; denominator the per-neuron total input synapse count from the optional Codex table. Without that table the result is `unknown` for every population. Populations below `completeness_min` trip.
- Population Fano factor (every run, online). From `hist_1ms` of recorded chunks, accumulated per probe: `F = var(c_b) / mean(c_b)` over 1 ms bins; the null under independent Poisson firing is 1. It trips at `F > sync_fano_max` (3) or when any bin holds more than `sync_bin_fraction_max` (0.05) of all neurons; `mean(c_b) == 0` gives `unknown` ("no activity"). This is a bursting detector, not a rate detector: hot states with F between 2.6 and 3.0 are rejected by K1 rate terms, not by lowering the threshold. Resting and level-2 measurements exclude 2 s settle before the 10 s observation; 5 s results are screening only. The settled ratio-4 seed-0 10 s F is 2.59, with a weak 12.6 Hz feature, and does not by itself qualify a resting state. (item 25) (item 43) (item 46)
- Weight-jitter robustness (only in suites 2.4 and 4.8, otherwise `not run`). Rerun with `jitter_seeds` log-normal `set_weight_scale` arrays from the `JITTER` stream; a headline paired difference that changes sign across jitter seeds is reported "not robust to weights".
- Encoder-permutation robustness (only in suite 4.8, otherwise `not run`). Rerun the 4.2 protocol with `encoder_perms` permutations from the `ENCODER` stream; a conclusion that does not survive all is reported "encoder-dependent".
- Curated-versus-predicted label check (every run). For every population, the count of members whose `top_nt` disagrees with the population's expected transmitter, and the count of Kenyon cells the prediction calls dopaminergic; trips if any population was defined through `top_nt`.
