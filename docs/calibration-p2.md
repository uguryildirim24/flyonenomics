# Phase 2 rest calibration

WP19 implements the section 2.5 chain through WP15's `scripts/calibrate.py --phase 2` registry. No rest configuration is committed until a measured WP17 ranked candidate is available. No qualification has been executed at this checkpoint.

`uv run python scripts/bench.py --plan FILE` expands repeats and reports arm, seed, probe and duration factors, using `budget.plan_settle_s` (2 s). Dose/wait phases add no simulated brain seconds. This is section 6.3 planning, not the more conservative section 6.4 wall budget.

R4 consumes `validation/records/p2/R2.json` with WP17's `decision.ranked` list of candidate dictionaries (`g_gaba`, `g_glu`, `w_bg`, `sigma_th`, `optic_exemption`, `n_bg`, optional `scope`). Candidate IDs follow WP17's parameter tuple; Camber job IDs come from each candidate's provenance. The adapter was checked against producer commit dc78c93; flattened ranked records are also accepted. R3 supplies `candidates` rows (`candidate_id`, `passed`) and a terminal `status` when screening completes. The R2 git commit timestamp starts the 12-hour deadline. The measured ranked file has not landed; verify its committed bytes when WP17 signals RANKED. Empty rankings need a recorded P2-partial-B escalation.

Before K1r, run `uv run python scripts/bench.py --b1-rest --workers auto`. When a selected R4 candidate exists but the final drive file does not, the benchmark materializes that candidate's common-weight bytes under `.cache/wp19-b1-candidate.yaml`; it does not invent a point or freeze it as the final drive. `--drive PATH` can instead name an existing loader-valid candidate configuration. The result records its SHA-256, q1, build/run time and memory. A q1 above 30 wall s/brain s requires coordinator notification and budget rescaling.

K1r is speculative parallel coordinate descent with exact serial replay (DEV-W19-K1R-PAR). Each round evaluates the next serial points in fresh processes. The recorded result is the serial algorithm's result. Seed 1, clamped pools, 2 s settle plus 5 s measurement, at most 40 serial evaluations including C. Coordinate moves remain within ±0.10 mV of each nonsensory common weight. F >= 3, b >= 0.05, central > 8 Hz or uncomputable metrics cannot win. T is chosen only when J improves by at least 20%; otherwise C remains selected. Sensory drive remains zero.

The drive stage commits prior evidence, then commits only `data/drive-v0.2.yaml`. It uses the WP15 loader keys, numeric group sizes/weights, scale-array and threshold-array hashes, transmitter blob and evidence provenance. K2r similarly records its three clamped 2+5 s measurements, computes continuous alpha/S_c, commits evidence, then commits only `data/dopamine-v0.2.yaml`. Neither configuration carries a qualification flag. All stage and entry outputs retain their launch identity; earlier bytes' evidence is archived before replacement.

`uv run python scripts/bench.py --b2-rest --workers auto` invokes Q-rest. SPEC-P2 section 6.4 defines B2-rest as that execution itself, so it cannot precede R4/K1r/K2r. Q-rest evaluates 3.1br, 2.3r, 2.7r, 2.6r, 2.2r, 1.4r, 1.4r-ff and 2.4r in order and stops at the first failure; 2.1r and benchmark evidence are retained. Feed-forward twins are checked by the entry code for exact matched seeds, windows, layers and modes; other scales-only files cannot qualify through this entry.

Only a 3.1br dopamine-window failure triggers re-estimation, using measured free-pool weighted DAN rates; at most three dopamine iterations run. A failed T records the C fall-through; a failed C records selection from remaining ranked candidates, or P2-partial-B after three failed candidates or exhaustion. Re-running the dispatcher advances the recorded fall-through through a new configuration commit. Previous evidence never qualifies new bytes.

Every child builds one network. Independent seed jobs use the shared auto slot lease and a fresh spawned child for each job. K1r leases workers for speculative rounds and replays the serial descent from the cache. The start check requires no competing engines and swap <=4000 MiB. Workers flush dependency logs before returning. The benchmark keeps granted concurrency, probe wall time, build and aggregation time, total brain seconds, mean settle and peak per-worker RSS. Aggregate q2 is reported separately for each granted concurrency; use section 6.4's 1.25 margin and build/aggregation costs, not total-wall/brain as a substitute for q2.

Code-only verification covers selection/deadline, bounded tuning, configuration-only commits, preserved evidence, algebra boundaries, complete seed sets, strict criterion edges, feed-forward fixture negatives, and a constructed end-to-end Q-rest ordering/failure path. Engine behavior is unverified until the selected candidate arrives.
